# navi-cheats

> [!WARNING]
> This README was generated by AI and may contain mistakes. Check the commands before you run them.

My personal cheatsheets for [navi](https://github.com/denisidoro/navi), an interactive command-line cheatsheet tool. Each `.cheat` file in this repo holds commands I use but don't want to memorize, so I can search for them and fill in their arguments from the terminal.

## Link this repo to navi

Requires [navi](https://github.com/denisidoro/navi) and `git`. Choose one of these options:

| Option | Best for | How to update |
| --- | --- | --- |
| [Import a copy](#option-1-import-a-copy) | Just using the cheatsheets | Run the import again |
| [Clone into navi's cheats folder](#option-2-clone-into-navis-cheats-folder) | Using the cheatsheets and pulling updates with git | `git pull` |
| [Add an existing clone to the config](#option-3-add-an-existing-clone-to-the-config) | Editing the cheatsheets, with changes showing up in navi right away | `git pull` |

### Option 1: Import a copy

```sh
navi repo add steffennilsen/navi-cheats
```

When prompted, choose whether to import all the files or select specific ones. navi copies them to `<cheats-path>/steffennilsen__navi-cheats`. The copy isn't connected to this repo, so run the command again to get updates.

### Option 2: Clone into navi's cheats folder

```sh
git clone https://github.com/steffennilsen/navi-cheats \
  "$(navi info cheats-path)/steffennilsen__navi-cheats"
```

navi finds the cheatsheets automatically. If you already used Option 1, delete the imported folder first, as `git clone` won't write into a folder that already has files in it.

### Option 3: Add an existing clone to the config

Add the clone to `cheats.paths` in navi's config file, which you can find by running `navi info config-path`:

```yaml
cheats:
  paths:
    - /path/to/navi-cheats
    - /path/to/default/cheats # the output of `navi info cheats-path`
```

Setting `cheats.paths` replaces navi's default location, so keep the second entry if you want to go on using cheatsheets stored there.

If the config file doesn't exist yet, create it at that path. To generate a full example to start from, run:

```sh
navi info config-example > "$(navi info config-path)"
```

This overwrites any existing config. The parent folder must already exist.
